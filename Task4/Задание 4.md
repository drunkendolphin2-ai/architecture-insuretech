# Решение
1) При создании заявки core отправляет событие в топик
2) Агрегатор читает топик, сохраняет в базу данных
3) Агрегатор с помощью крон джобы отправляет запросы страховым компаниям, сохранят заявку в статусе PROCESSING
4) Агрегатор с помощью крон джобы запрашивает информацию по решению у страховых компаний по заявкам в статусе PROCESSING, сохраняет ответ
5) Веб через core периодически полит статус заявки, core сохранят статус, отображает клиенту

# API
## Веб и core
1) Веб отправляет заявку, core присваивает id заявке, отправляет необходимую информацию в топик, возвращает id заявки вебу
2) Веб polling по id заявки

## core и агрегатор
1) Топик - id заявки в core, информация по клиенту, информация по услуге, доп.фильтры (например запрос только по конкретных страховым)
2) Запрос информации по заявке - id заявки в core, возвращаются статус и решения страховых компаний.

# Дополнительно
1) Поскольку партнеров мы ожидаем максимум 60 секунд нужно установить таймаут.
2) Ретраи в агрегаторе нужны только при запросе решений по заявке, в противном случае может быть ситуация, когда партнер принял заявку, начал ее обработку, ответил ошибкой, и агрегатор снова отправляет запрос на создание заявки
