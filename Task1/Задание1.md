# Определите стратегию масштабирования и отказоустойчивости.

Для данной системы более разумным будет использование горизонтального масштабирования для сервисов по нескольким причинам:
1) В долгосрочной перспективе увеличение мощности сервера не способно покрыть требования по 99.9 доступности и RPO.
2) Поскольку продукт планируется запускать в нескольких регионах России - разумно распределить нагрузку по этим регионам

Однако для БД хватит и вертикального, объем данных небольшой.

Дополнительные зоны доступности - обязательны, без них невозможно обеспечить целевые показатели по SLA, RTO и RPO. Помимо этого трафик в регионах можно будет распределить по серверам.
